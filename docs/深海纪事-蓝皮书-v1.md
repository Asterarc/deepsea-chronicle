# 《深海纪事》蓝皮书 v1

> 一个由粉丝共同养成的、AI 自动运营的像素海洋世界，以及从中长出的短视频内容。
> 本文给完全不了解这个项目的人看：它是什么、为什么成立、怎么运营、怎么实现。



## 0. 一句话说清

**每一个关注者在这片海里有一条属于他自己的像素小鱼。**

这条鱼会老、会交朋友、会结仇、会跟着鱼群出海、会在风暴里掉活力。
每天有一期 100 秒的视频，从几十万条鱼里挑出 30 条来讲它们昨天发生了什么——
**其中 3 条会被展开成完整的 15 秒小传。**

它不是一个"宠物号"，是一个**世界**：视频只是这个世界的新闻联播。

## 1. 这是什么

### 1.1 产品形态表

| 层 | 是什么 | 用户在哪儿接触 |
|---|---|---|
| **世界层** | 一份持续演化的鱼群数据库：鱼、关系、事件、世代 | 后台，用户看不见 |
| **内容层** | 每天 100 秒成片，抖音竖屏 | 抖音 |
| **互动层** | 可点的像素海洋小游戏 | 网页 `http://127.0.0.1:3080/ocean/` |
| **身份层** | 编号、世代、纪念碑、年鉴 | 未来变现的主战场 |

### 1.2 和现有 AI 萌宠账号的根本区别

| | 现有 AI 萌宠号 | 深海纪事 |
|---|---|---|
| 关系 | **一对多**：我养两只猫，你们看 | **多对一**：几万条鱼，每条绑一个真人 |
| 内容源 | 博主写剧本 | **世界数据自己长出故事** |
| 护城河 | 人设（可被抄） | **鱼群关系网（抄不走）** |
| 成本痛点 | 每期要新剧本 | 每期要处理几十万条状态 |
| 天花板 | 广告 | 广告 + 身份 + IP 授权 |

行业坐标：#AI萌宠 在抖音累计播放 26.4 亿，12.4 万创作者在场。
已验证的爆款公式是「**人的行为逻辑 + 动物的可爱外形 + 连续剧式的连贯人设**」，
其中最值钱的一句评价是：**"看似是猫生，其实是人生。"**

深海纪事把这个公式推到极端：不是两只猫演人，是**几十万条鱼各演各的人**。

## 2. 它为什么成立

三个心理机制同时生效，缺一个整体留存就会塌一半。

### 2.1 拥有感（我的鱼）

- 每条鱼有**永久唯一编号**（`#0374`），不可重置、不可转让
- 一人一鱼，绑定关系不解除
- 编号是身份，不是属性——鱼可以死，编号不会消失

### 2.2 连续性（它的故事还没讲完）

- 鱼有跨天的记忆：昨天跟谁吵了架，今天还会躲着它
- 关系有强度值，会自然衰减（长期不往来就淡了）
- 每期结尾必留悬念：明晚的议程、明晚的危险

### 2.3 集体性（我是居民，不是观众）

- 每周一次全城投票，结果直接决定下期拍哪儿
- 高赞评论不是"素材"，是**提案**
- 内部黑话体系：珊瑚城、深水区、远航、二世、望族——外人听不懂，内部人自豪

### 2.4 最关键的一条：叙事是**读**出来的，不是编出来的

| 别家 | 深海纪事 |
|---|---|
| 编剧写："小猫今天去上班了" | 引擎读：`#0374` 连续三天在浅滩，活力 12，今天自动触发「搬家」 |
| 靠灵感，会枯竭 | 靠状态机，永续 |
| AI 写出来套路化 | 数据本身就是具体到离谱的 |

**具体性是唯一有效的"去 AI 味"手段。**
"海底很热闹" 是 AI 味；
"第 7 号礁石的老螃蟹今天第三次骂人，因为它藏的贝壳被人挪了 3 厘米" 是真人味。

## 3. 世界观设定

### 3.1 四个海区

| 海区 | 设定 | 风险系数 | 商业价值 |
|---|---|---|---|
| **浅滩** | 新鱼入海的第一片水域，光能照到底 | 0.10 | 新人入门仪式 |
| **珊瑚城** | 主城区，礁石密布，鱼口最稠 | 0.30 | 品牌冠名主力位 |
| **深水区** | 光到不了的地方，老资格鱼的领地 | 0.60 | 高端/尊贵感 |
| **沉船带** | 锈色船骸，事件和宝藏都在这儿 | 0.85 | 高流量事件位 |

> 海区不是地图，是**阶层和身份**，也是未来的广告库存。
> 现在先立文化，不急着卖冠名——等"深水区"变成观众嘴里的词，一个地名才卖得上价。

### 3.2 鱼的属性

```
id            唯一编号 #0374
name          小满 / 小满二世
generation    世代（1 = 初代）
species       10 种：灯鱼/小丑鱼/蝴蝶鱼/鹦嘴鱼/刺尾鱼/箱鲀/海马/狮子鱼/比目鱼/鳐
palette       10 色：金/银/橙/青/紫/白/墨/绯/翠/琥珀
pattern       4 种花纹：纯色/竖条/斑点/腹部亮带（由编号决定）
trait         12 种性格：贪吃/胆小/好斗/爱干净/话多/孤僻/爱管闲事/护短/记仇/好奇心重/爱收藏/嘴硬心软
region        当前海区
vitality      活力 0-100
mood          心情 0-100
intimacy      与主人的亲密度（重生继承）
fame          名气
scars         伤痕数 = 经历过的重大事件数
status        alive / hatching / soul
```

**性格决定行为概率**：好斗的鱼更容易结仇，孤僻的鱼不主动交朋友，爱收藏的鱼洞里亮片多。

### 3.3 世代系统（这是本项目最独特的一层）

鱼不会"死"，会**远航**——然后同一个人立刻获得同名的"二世"：

```
#0374 小满（一世）  远航于第 3 次风暴
        ↓
#0374 小满二世      孵化为一条小鱼，从头开始
```

| 项目 | 继承？ | 理由 |
|---|---|---|
| 编号 | ✅ 永久不变 | 编号是身份 |
| 与主人的亲密度 | ✅ 保留 | 这是"我"和"它"的关系，不是它的属性 |
| 关系网 | ✅ 全继承 | 一世的仇人是二世的仇人——剧情金矿 |
| 记忆（伤痕故事） | ✅ 保留 | "它父亲有三道伤痕" |
| 体型/等级/属性 | ❌ 归零 | 必须从头 |

> **一句话原则：它忘了自己有多强，但记得自己是谁的孩子。**

世代带来的意外收益：

- **无限进度条**：v1 方案里进度靠"体长"，但体长会到顶；**世代不会**
- **社交货币**："我家鱼已经第 7 世了"本身就能炫耀
- **解决了鱼无限长大**：轮回了，画面永远是各世代混杂的真实生态

| 世代 | 称号 | 特权 |
|---|---|---|
| 一世 | 新鱼 | 无 |
| 二世 | 归来者 | 名字后缀 |
| 三世 | 老渔户 | 可发起投票 |
| 五世 | 望族 | 进望族名录 |
| 十世 | 传说 | 独立纪录片 |

### 3.4 关系网

```
fish_relationships
  a, b          两条鱼
  type          friend / rival / lover / mentor
  strength      0-100
  since         建立于第几天
```

三条规则：
1. **社交上限 8 条**——不加这条，180 天后平均每条鱼 20 个关系，"我的死对头"就没有意义了
2. **自然配对**：同海区、性格不冲突、双方未满额 → 有概率成为朋友或结仇
3. **会淡**：每 3 天强度 -0.5，低于 2 就自然散伙

> 没有关系就没有戏剧；没有戏剧，就只能播报数据。而播报数据的账号三天就腻。

## 4. 内容产品形态：100 秒

### 4.1 分段时间表

| 秒 | 段落 | 干什么 |
|---|---|---|
| 0–3 | **钩子** | 一条鱼逼近镜头，编号牌浮出，"它今天出了点事" |
| 3–18 | **PK 计票** | 左右两屏，双方名字逐条砸入并常驻，数字疯狂跳动 |
| 18–20 | **揭晓** | 白光爆开，镜头俯冲进获胜海区 |
| 20–65 | **三条主角** | 各 15 秒，每条有天/昨天/前天的时间锚 |
| 65–92 | **群像点名** | 27 条鱼逐个点亮，编号角标 |
| 92–100 | **收尾** | 灵魂光点上浮，"你的鱼，在名单上吗？" |

### 4.2 三池选材（每期 30 条）

| 池 | 怎么选 | 给谁看 | 时长处理 |
|---|---|---|---|
| **人气榜 Top10** | 名气 × 年龄 × 伤痕 × 世代 | 老粉（炫耀欲） | 出 1 条当主角 |
| **节目效果 Top10** | 当日动作数 × 关系变动 × 偏离日常 | 内容粉（吃瓜） | 出 1 条当主角 |
| **随机 Top10** | 加权随机，**从没上过镜的权重最高** | 路人（"下次是我"） | 出 1 条当主角 |

剩下的 27 条进群像网格，每条带画面坐标。

> 三池结构解决了一个死结：只按人气选，新人永远没机会；只随机，内容没有高潮。
> 各出一条主角，三种人都被照顾到。

### 4.3 PK 计票：本项目最强的互动设计

**不要问"去哪个海区"，要问"该不该逃"。**

| | 效果 |
|---|---|
| ❌ "去浅滩还是深水区？" | 观众没理由站队 |
| ✅ "渔民来了，深水区的鱼该不该逃？" | 立刻分裂，评论区开战 |

**让投票本身成为剧情，海区只是结果。**

计票动画三段式：

```
① 逐条入场 10s   前 10 条高赞评论带头像+昵称，一条一条砸进左/右阵营
                  → 作用：让观众在片子里找到自己的名字
② 名字瀑布 5s    剩下几千条昵称快速滚过，数字疯狂跳动
                  → 作用：制造"我也在里面"的确认感
③ 定格反转 3s    差距 <6% 时做"最后三秒逆转"
                  → 作用：本期节目效果峰值
```

> **按点赞数累计，不是按人头。** 这才是抖音的真实计票方式，也才撑得起"左边 +240、右边 +236"的累积快感。

## 5. 事件系统

### 5.1 节奏比例

| 频率 | 类型 | 作用 |
|---|---|---|
| 70% | 平静日 | 建立基线，让大事件有对比 |
| 20% | 小事件（水母潮/深海发光/陌生鱼群/珊瑚吐卵） | 日常谈资 |
| 8% | 中事件（洋流北上/水温异常/赤潮预警） | 周内悬念 |
| 2% | 大事件（风暴/拖网船/鲸落/沉船发现） | "我在乎"的时刻 |

### 5.2 关键设计：**事件改状态，不改生死**

风暴扣活力、拖网擦伤、赤潮预警——**都不会杀死鱼**。
世界里唯一的"死"法是**远征**，而且是玩家自己决定的。

### 5.3 远征：把死亡变成共谋

```
发起 → 集结盖楼 → 24 小时反悔窗口 → 出发 → 灵魂入海 → 分批重生
```

- 每天 2 位发起者（1 人气 + 1 随机）从预设选项里选：跟鲸群往北 / 下潜沉船带 / 跟洋流散步
- 其他人回复报名，满 50 条才出发
- **出发前公布完整名单，给 24 小时反悔期**——这段本身就是全片最有张力的部分
- **远航率控制在 60–70%**，剩下带伤回来，还要**带回故事**（一枚硬币、一次鲸落）
- 重生按孵化期分批（D+3 / D+5 / D+7），避免生态瞬间断层

> 系统杀死你的鱼，你会愤怒；你和 100 个人一起决定去送死，你会截图留念。

### 5.4 动作库：32 个动作，三层

| 层 | 例子 | 触发 | 作用 |
|---|---|---|---|
| **微动作**（1–3 秒） | 掏鱼粮、对着石头看、追尾巴、照贝壳、躲岩缝、装死、抖鳍炫耀 | 饿 / 无聊 / 害怕 / 得意 | 制造"它在想事"的错觉 |
| **长行为**（数小时） | 建洞穴、整理洞穴、收藏亮片、养海草、搬家、跟踪、巡领地 | 待够天数 / 关系值 | 制造"它有生活" |
| **关系事件**（跨天） | 吵架、送礼、结盟 | 关系值过阈值 | 制造"它有感情"，故事核 |

**所有动作都绑定状态，没有无来由的动作。**

```
无聊 → 建洞穴 → 被别的鱼占了 → 吵架 → 打输 → 躲起来 → 又饿 → 掏鱼粮
```
这就是一条完整的三幕剧，而且**没有一句是编出来的，全是状态撞出来的**。

## 6. 运营模式

### 6.1 每日节奏

```
09:00  引擎自动推进一天 → 生成待审清单（out/day-XXXX.md）
09:05  人过审核门（5 分钟）
09:15  开拍/合成
       ↓
      成片 100 秒，发布
```

### 6.2 审核门（不可省）

每期清单开头有 5 条必过项：

- [ ] 有没有点名到真实用户？确认已获同意或已脱敏
- [ ] 有没有广告/品牌元素？有则加"广告"标识
- [ ] 发布时勾选"内容由 AI 生成"
- [ ] 有鱼在远征里远航吗？确认已在评论区提前公示
- [ ] 文案里没有出现"死""自杀""送死"字样

> 全自动无人值守的账号，出一次事故就归零。审核门是这套系统能活过一年的前提。

### 6.3 评论怎么进来（半自动）

抖音开放平台的评论接口属于**企业开放能力**（`comment-management-enterprise`），个人创作者拿不到；自动发布同样需要企业资质。

所以设计成"丢文件"：

```
人工导出置顶评论回复 → inbox/votes.json → 引擎自动计票
```

没有这个文件时用内置模拟数据（方便联调）。

**一天花 5 分钟在导出上，省掉的是每天 4 小时想脚本、算名单、写分镜。**

## 7. 抖音策略与变现

### 7.1 平台硬约束

| 约束 | 数值 / 事实 |
|---|---|
| 完播率 | 60 秒视频到 30% 就算不错；90 秒在冷启动阶段基本起不来 |
| AI 成本 | 视频生成约 1 元/秒，且要乘 3–8 次重试的出错率 |
| 内容长度 | 市面上很少有几分钟的视频，基本几十秒到两分钟 |
| 合规 | AI 生成内容必须显著标识；不得诱导互动；不得引导站外 |

**结论：正片 100 秒、日更，而不是 3 分钟、周更。**

### 7.2 广告位地图（第一天就要开始埋）

| 广告位 | 世界观包装 | 适配品类 | 反感度 |
|---|---|---|---|
| 地标冠名 | "XX 礁""XX 湾"进入地图 | 文旅、汽车、地产 | 极低 |
| 船只植入 | 印着 logo 的船驶入珊瑚城 | 食品饮料、3C | 低 |
| 新物种 | 品牌 IP 变成海里的一种生物 | 游戏、潮玩、IP | 极低 |
| 沉船事件 | 打捞上来一个品牌的"宝藏" | 电商、盲盒 | 中低 |
| 季节联名 | "XX 杯珊瑚城风暴季" | 全品类 | 低 |
| 纪念碑 | 碑林整体冠名 | 环保公益、保险 | 低 |

**三条铁律：**
1. 广告藏在"事件"里，不放在"台词"里
2. 从第一天起就反复提"北边那片礁石"，但**先不起固定名**——那是将来卖的期权
3. 广告主买的是**人群**不是播放量：18–30 岁、偏女性、有陪伴需求、养宠倾向

> 已验证：@飘莉哩 的猫生活里自然出现某饮料品牌，观众反而去问"这饮料是真的存在吗"，
> 品牌官方认领投放，不但没掉粉还带出了外地销量。

### 7.3 变现三层

| 层 | 产品 | 毛利 | 时机 |
|---|---|---|---|
| 现金流 | 广告 / 冠名 | 中 | 1 万粉后 |
| **高毛利** | **身份**：编号居民证、年鉴、命名权、专属档案 | 高 | 3 万粉后 |
| 天花板 | IP 授权：动画、游戏、实体 | 极高 | 成熟期 |

> 卖"我是这座城的老居民"，比卖"多看一集"值钱得多。

## 8. 技术架构

### 8.1 总图

```
┌─────────────────────────────────────────────────────────┐
│  世界层（持续演化）                                        │
│  world.json ← 模拟引擎（老化/动作/关系/事件/孵化）          │
└───────────┬───────────────────────────┬─────────────────┘
            │                           │
     ┌──────▼──────┐            ┌───────▼────────┐
     │  内容层      │            │  互动层         │
     │  100 秒成片  │            │  像素海洋游戏   │
     └──────┬──────┘            └───────┬────────┘
            │                           │
     ┌──────▼──────┐            ┌───────▼────────┐
     │ 逐帧渲染     │            │ canvas 实时     │
     │ + 中文字幕   │            │ + WebAudio      │
     │ + 音效       │            │ 事件状态机      │
     └──────┬──────┘            └───────┬────────┘
            │                           │
            └───────────┬───────────────┘
                        │
              ┌─────────▼──────────┐
              │ web/sprites.js      │
              │ 唯一真源：调色板     │
              │ 鱼形/描边/大眼/花纹  │
              └────────────────────┘
```

### 8.2 为什么是这套架构

| 决定 | 理由 |
|---|---|
| **纯 JS 光栅 + 自写 PNG 编码** | 不装 canvas/sharp，不带原生依赖，换台机器直接跑 |
| **低分辨率绘制 + 最近邻放大** | 像素风格的天然做法，同时把像素运算量压到 1/4 |
| **中文字幕交给 ffmpeg drawtext** | 命令行传 Unicode 会乱码，必须走 textfile |
| **精灵单一真源** | 游戏和视频是同一个画风，不是两套美术 |
| **状态存 JSON 而不是数据库** | 原型期无痛；结构已按 SQL 设计，换库只改一层 |

## 9. 模拟内核

### 9.1 每日推进（tick）七步

```
1. 孵化：上一世的鱼破壳归来（status: hatching → alive）
2. 每条活鱼：老化 + 活力漂移 + 动作抽取（1-2 个微动作，可能触发长行为/关系事件）
3. 主动迁徙：活力过低的鱼往更浅的海区游
4. 结关系：同海区自然配对，受社交上限 8 约束
4b. 关系衰减：每 3 天强度 -0.5，太弱的散伙
5. 事件判定：70/20/8/2 权重抽取
6. 新鱼入海（模拟真实增长）
7. 归档日志（保留 14 天）
```

### 9.2 活力模型（调过两版）

```
drift = (58 - vitality) * 0.07      // 均值回归，向 58 收敛
      + random(-3.5, 3.5)           // 日常波动
      + friends * 1.3               // 有朋友回血
      - rivals * 1.6                // 有对头掉血
      - regionRisk * 3              // 海区越深越耗
      + (generation >= 3 ? 1 : 0)   // 老鱼更耐
```

> 第一版是单向衰减，跑 30 天后**全员饿死**。改成均值回归才稳。

## 10. 视觉资产

### 10.1 风格选择：可爱像素

| 候选 | 优势 | 风险 | 结论 |
|---|---|---|---|
| 半写实 3D 海洋 | 治愈感最强 | 单鱼一致性最难，成本最高 | ❌ |
| 2D 水彩 | 一致性好做 | 批量化成本高 | ✅ 已实现并保留 |
| **可爱像素** | 天然游戏感，成本最低，可批量，能做动作资产复用 | 广告主接受度略低 | ✅ **当前默认** |

### 10.2 精灵规格

```
28 × 18 像素，16 色调色板
流程：画实心块 → 统一外扩 1px 描边 → 压上 5×5 大眼 + 一颗腮红
花纹 4 种（纯色/竖条/斑点/腹部亮带），由编号决定
```

> **大眼和腮红是"可爱"的唯一来源。** 没有它们，鱼就是一块几何体。

### 10.3 背景

用**Bayer 有序抖动**做渐变，而不是平滑过渡——这是像素画特有的水下光感。
关键：色阶必须是**相邻色**，跨度太大会出现"纱窗"。

## 11. 成片流水线

### 11.1 三阶段

```
① 180×320 逻辑像素绘制（逐帧）
        ↓ 最近邻 3×
② 540×960 + 中文字幕（逐字弹出，154 层 drawtext）
        ↓ 最近邻 2×
③ 1080×1920 H.264 + AAC
```

### 11.2 实测性能

| 指标 | 数值 |
|---|---|
| 100 秒 × 24fps | 2400 帧 |
| 纯 JS 渲染 + 编码 | **约 11 秒**（零 GPU、零原生依赖） |
| 音频生成 | 约 1 秒（152 个音效 + 氛围垫） |
| 成片体积 | 7.5 MB |

### 11.3 音频：没有配音

| 音 | 触发 | 音色 |
|---|---|---|
| 字母弹出 | 每个 2 字块出现时 | 三角波，520–700Hz，55ms 快速衰减 |
| 名字落位 | PK 里每个昵称入场 | 正弦闷响，A 侧 760Hz / B 侧 640Hz |
| 转场 | 18.3s / 65.2s / 92.2s | 噪声扫频 |
| 氛围垫 | 全程 | 55Hz 持续低音 + 滤波噪声 + 随机气泡 |

> 试过 TTS 中文配音，机械感重，反而破坏像素风。改成滴滴声+逐字弹出，节奏感强得多。

### 11.4 踩过的坑（都已绕过）

| 坑 | 现象 | 解法 |
|---|---|---|
| `fontfile=` 相对路径 | 静默回退到无中文字体，整屏方框 | 必须绝对路径且转义：`'C\:/Windows/Fonts/simhei.ttf'` |
| PowerShell 传中文参数 | 乱码 | 全部改走 `textfile=` |
| 滤镜链过长 | 撞 Windows 8191 字符命令行上限 | 写进 `-filter_script:v` 文件 |
| 字幕只设下界 | 第一段文字挂到片尾 | 改成 `gte(t,开始)*lte(t,结束)` |
| `bg.height = VH` 后接 IIFE | 被解析成函数调用 | 行尾补分号 |

### 12.3 为什么要有游戏层

视频是**一次性的**，游戏是**可反复进入的**。

- 视频负责拉新（抖音）
- 游戏负责留存（"上去看看我的鱼现在在干嘛"）
- 两者共用同一份世界数据、同一套精灵资产
